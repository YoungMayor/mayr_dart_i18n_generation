# 🌍 mayr_i18n_generator

### Code generation for [`mayr_i18n`](https://pub.dev/packages/mayr_i18n)

`mayr_i18n_generator` provides automatic **type-safe translation key generation** for projects using `mayr_i18n`.
It scans your JSON language files and generates Dart classes with structured translation keys and autocompletion support — making localization clean, reliable, and developer-friendly.

---

## 🚀 Installation

Add the packages to your `pubspec.yaml`:

```yaml
dependencies:
  mayr_i18n: ^1.0.0

dev_dependencies:
  build_runner: ^2.4.0
  mayr_i18n_generator: ^1.0.0
```

---

## ⚙️ Configuration

In your root `pubspec.yaml`, configure your translation settings under `mayr_i18n`:

```yaml
mayr_i18n:
  lang_directory: assets/lang   # Directory containing JSON language files
  default_locale: en            # Default locale key

mayr_i18n_generation:
  output_file: lib/translations.dart  # File to generate code for (default: lib/generated/translations.dart)
```

**Note**: The `output_file` configuration specifies which file the generator should process. This prevents conflicts with other code generators (like `json_serializable`, `freezed`, etc.) that also create `.g.dart` files. If not specified, it defaults to `lib/generated/translations.dart`.

Example directory structure:

```
assets/
  lang/
    en.json
    fr.json
    genz.json
lib/
  translations.dart  # Your file with part directive
  translations.g.dart  # Generated by build_runner
```

## 🧠 Example

### 1️⃣ Define your translation JSON

```json
{
  "app": {
    "welcome": "Welcome {name}",
    "logout": "Goodbye"
  },
  "errors": {
    "network": "No internet connection"
  }
}
```

---

### 2️⃣ Create `lib/translations.dart`

```dart
import 'package:mayr_i18n/mayr_i18n.dart';

part 'translations.g.dart';
```

---

### 3️⃣ Generate code

Run the build command:

```bash
dart run build_runner build
```

✅ This generates `lib/translations.g.dart`:

```dart
// GENERATED CODE - DO NOT MODIFY BY HAND
// ignore_for_file: constant_identifier_names, non_constant_identifier_names

part of 'translations.dart';

class I18nKeys {
  static const app = _AppKeys();
  static const errors = _ErrorKeys();
}

class _AppKeys {
  final welcome = 'app.welcome';
  final logout = 'app.logout';
}

class _ErrorKeys {
  final network = 'errors.network';
}
```

---

### 4️⃣ Use it in code

```dart
final greeting = I18nKeys.app.welcome.tr(args: {'name': 'Mayor'});
print(greeting); // "Welcome Mayor"
```

Or access by string:

```dart
print('app.welcome'.tr()); // "Goodbye"
```

## 🔧 Manual Code Generation

If you prefer to generate code manually instead of using `build_runner`, you can use the CLI command:

```bash
dart run mayr_i18n_generator:generate
```

This will:
- Find all Dart files with `.g.dart` part directives
- Read your JSON translation files
- Generate type-safe translation key classes

**Note**: Additional CLI commands for verification, syncing, and auditing translations are available in the [`mayr_i18n`](https://pub.dev/packages/mayr_i18n) package.

---

## 🧩 build.yaml (optional)

You can customize generation with a `build.yaml` (not required):

```yaml
targets:
  $default:
    builders:
      mayr_i18n_generator:
        generate_for:
          - lib/**.dart
builders:
  mayr_i18n_generator:
    import: "package:mayr_i18n_generator/mayr_i18n_generator.dart"
    builder_factories: ["i18nBuilder"]
    build_extensions: {".dart": [".g.dart"]}
    auto_apply: dependents
    build_to: source
```

## 💡 Advanced

### Code generation shortcut

You can run directly:

```bash
dart run mayr_i18n_generator:generate
```

instead of using `build_runner`.

### Supports Nested JSON

```json
{
  "profile": {
    "name": "Name",
    "details": {
      "age": "Age",
      "email": "Email"
    }
  }
}
```

Accessed as:

```dart
I18nKeys.profile.details.email.tr();
```
